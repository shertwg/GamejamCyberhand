## Запуск на Godot 4.4.1

Открыть **project.godot из этой отдельной копии**, затем
`game/side_expedition/quiet_signal.tscn` и нажать **F6** (запуск текущей сцены).
F5 запускает прежнюю главную сцену: настройки проекта намеренно сохранены.

Либо из корня отдельной копии:

```powershell
godot --path . res://game/side_expedition/quiet_signal.tscn
```

Если Godot отсутствует в PATH, заменить `godot` на вызов своего исполняемого
файла 4.4.1: `& 'путь\Godot_v4.4.1-stable_win64_console.exe'`.

Нажать «Выйти из шлюза». Клавиатура: **A / W / ↑** — вверх, **B / S / D / ↓** —
вниз. Мышью или пальцами — удерживать соответствующие подписанные кнопки [ЭМУЛ].
Отпускание останавливает действие и игровые часы. Кнопка руки зеркалит панель,
после переключения нужен нейтральный ввод и «Продолжить».

## Игровой маршрут

| Этап | Игровая задача | Открытие истории |
|---|---|---|
| Сигнал | Выйти из шлюза, пройти ущелье к маяку | У Керны есть неизвестный позывной |
| Детали | Совместить захват с тремя уцелевшими деталями | Разведчик «Север-3» прибыл раньше нас |
| Переходник | Три соединения A → нейтраль → B → нейтраль → A | Наш инструмент несовместим с чужим блоком |
| Блок питания | Подвести и стабилизировать каретку замка | В записи прежней группы: «Мы тоже шли на этот сигнал» |
| Возвращение | Доставить видимую аварийную батарею в левый шлюз через бурю | Чужой журнал сохранён, история прежней экспедиции остаётся открытой |

Ущелье проходится в обе стороны; при касании скалы продвижение блокируется,
игрок может изменить высоту. Буря даёт плавный видимый вертикальный снос,
пропорциональный intensity: слабый разрешённый сигнал остаётся управляемым.
Покой, BOTH и потеря потока замораживают ветер, частицы, задачи и часы.
Встречный сигнал восстанавливается через нейтраль; потеря потока, пауза и
возврат из фона — через нейтраль и явное «Продолжить».

В сборке каждый выполненный контакт сохраняется до окончания текущего запуска.
Зажатый канал не завершает несколько соединений: между ними требуется REST.
Вскрытие блока питания — отдельный режим без автопродвижения по X, поэтому цель
стабилизации выполнима обычными кнопками 0/1. Intensity=0 не набирает прогресс.
Отдых приостанавливает накопленное удержание, не отнимая его.

Журнал доступен отдельной кнопкой; чтение приостанавливает ввод. После закрытия
следует явно продолжить. Повествовательные названия и формулировки — локальная
версия для согласования с сюжетной линией кампании.

## Архитектура и точки интеграции

- `expedition_model.gd` — независимое состояние, правила и сюжетные этапы;
  принимает `advance(delta, ControlCommand)`, не читает устройства и файлы.
- `quiet_signal.gd` / `.tscn` — отдельный запускаемый интерфейс и host.
- `signal_adapter.gd` — только эмуляция каналов клавиатурой/сенсором.
- `expedition_view.gd` — процедурное рисование; эффекты используют часы модели.

Локальный поток: адаптер → неизменённый ManualInputSource → неизменённый
InputPipeline → ControlCommand → модель. Профиль по умолчанию — существующий
эмулятор 0.55/0.40; heartbeat 50 мс, watchdog 250 мс. Сохранение игрока не читается.
Для самостоятельного режима читаются существующие `manual_pad.gd` и
`terminal_style.gd`; их исходники не менялись.

Пример подключения из host кампании:

```gdscript
var expedition = preload("res://game/side_expedition/quiet_signal.tscn").instantiate()
# При необходимости назначить существующий InputConfig ДО add_child().
expedition.input_config = approved_campaign_input_config
expedition.expedition_completed.connect(_on_quiet_signal_completed)
expedition.journal_added.connect(_on_quiet_signal_journal)
expedition.exit_requested.connect(_on_quiet_signal_exit)
add_child(expedition)
expedition.start_expedition(campaign_run_id)
```

Эмулятор сцены предназначен для самостоятельного прогона. Для подключения
общего аппаратного/кампанийного источника использовать модель и её
`advance(delta, ControlCommand)` из существующего координатора, сохранив
нейтраль/resume/watchdog. Новый аппаратный адаптер здесь не реализован.

Сигналы корня:

- `stage_changed(stage_id: String)` — переход этапа.
- `journal_added(entry: Dictionary)` — `{id, title, body}`, копия для сюжетного журнала.
- `expedition_completed(result: Dictionary)` — один результат успешного запуска.
- `exit_requested(result: Dictionary)` — запрос выхода с текущим результатом.
  Если подключён обработчик, переход выполняет владелец кампании. При отдельном
  запуске без обработчика «Выход» закрывает тестовую игру.

Формат локального результата (не изменение `contracts/`):

```json
{
  "schema_version": 1,
  "expedition_id": "quiet_signal",
  "run_id": "id назначает host или создаёт отдельный запуск",
  "completed": true,
  "battery_secured": true,
  "crafted_items": ["scout_adapter"],
  "reward_proposal": [{"item_id": "emergency_battery", "amount": 1}],
  "discoveries": ["prior_expedition"],
  "journal": [],
  "stats": {"active_seconds": 0.0, "wall_contacts": 0}
}
```

Это предложение награды. Сцена не начисляет предметы, не регистрирует миссию
на карте, не записывает склад и не создаёт шкалы запасов. До возвращения
`reward_proposal` пуст. Владелец кампании определяет однократность награды по
`expedition_id` и защищает обработку одного запуска по `run_id`; не начислять
повторно и по completed-сигналу, и по последующему выходу. Повтор отдельного
прототипа начинает новый локальный запуск с пустыми деталями и новой батареей.

## Проверки

```powershell
godot --headless --path . --editor --import
godot --headless --path . --max-fps 120 --script res://game/side_expedition/tests/smoke.gd
godot --headless --path . --max-fps 120 --script res://qa/prototype_smoke.gd
```

Снимки интерфейса с GPU:

```powershell
godot --path . --max-fps 120 --script res://game/side_expedition/tests/smoke.gd -- --capture
```

Они появляются в игнорируемом `work/quiet_signal/`: альбомный, портретный,
компактный маршрут и отдельные этапы. Снимки используют явно обозначенные
синтетические состояния интерфейса; полные прохождения выполняются отдельно,
начиная от шлюза, без телепортации между этапами.

Фактическая проверка 10.11.2026 на `4.4.1.stable.official.49a5bc7b6`:

- Headless import: exit 0, ошибок GDScript в финальном импорте нет.
- Собственный headless smoke: **168 checks, 0 failures**, exit 0.
- Финальный GPU/capture smoke с `--max-fps 120`: **179 checks, 0 failures**, exit 0;
  проверены и просмотрены снимки этапов и прокручиваемого журнала.
- Проверяются шесть полных маршрутов: сигналы 0.65/1.0, шаги 16/50/200 мс,
  последовательность этапов, детали, сборка, возврат, журнал и результат один раз.
- Проверяются REST/BOTH/WAITING_NEUTRAL, focus/resume, watchdog, чтение журнала,
  клавиша B, пользовательский InputConfig, зеркалирование, выход без награды,
  нулевая интенсивность и обязательная нейтраль между соединениями.
- Для каждого этапа и полного журнала проверены размеры 1152×648, 648×1152 и 640×360.
- Штатный smoke основного проекта: **395 checks, 0 failures**, exit 0.
- Прямой запуск `.tscn` на 120 headless-кадров: exit 0.

В локальной среде есть диагностическое сообщение о недоступном хранилище
корневых сертификатов, при импорте — отсутствие Android build-tools.

Изменения проверялись с отдельными APPDATA/LOCALAPPDATA внутри `work/runtime`.

## Ограничения и передача

Android APK, физический телефон, реальные датчики и эргономика руки не проверены.
Визуал — кодовые примитивы, без внешних ассетов и звуковой дорожки.
Нагрузочное время алгоритма — около 31 с при полном сигнале и 124 с при 0.65;
чтение, реакция и ошибки игрока в эти значения не входят.

Для интеграции переносится только `game/side_expedition/`; затем подключаются
карта, сюжет и склад владельцем кампании. Shared-сцены, InputPipeline, contracts,
project.godot, экспорт, основная кампания и глобальные evidence-файлы не правились.
В соответствии с этой изоляцией журнал ИИ находится здесь:
`game/side_expedition/evidence/ai-log.csv`; запись о визуале — в соседнем assets.csv.
