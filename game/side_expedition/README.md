# «Тихий сигнал» — самостоятельный игровой прототип

10.11.2026. Отдельная копия репозитория:
`C:\dev\ruka\GamejamCyberhand-dima-quiet-signal`, ветка `feat/dima-gameplay`.
База — `85163d6`. Все изменения экспедиции находятся в `game/side_expedition/`.
Основная копия проекта и её рабочее дерево не использовались для разработки.

Текущий скелет квеста — три явные точки: **шлюз → поле обломков → остов разведчика**.
Возвращение проходит через то же поле обломков в шлюз. Переходы, точки
взаимодействия, реплики на входе и текущая цель уже доступны в запускаемой сцене.

## Запуск на Godot 4.4.1

Открыть **project.godot из этой отдельной копии**, затем
`game/side_expedition/quiet_signal.tscn` и нажать **F6** (запуск текущей сцены).
F5 запускает прежнюю главную сцену: настройки проекта намеренно сохранены.

Либо из корня отдельной копии:

```powershell
godot --path . res://game/side_expedition/quiet_signal.tscn
```

Если Godot отсутствует в PATH, заменить `godot` на вызов своего исполняемого
файла 4.4.1: `& 'путь\Godot_v4.4.1-stable_win64_console.exe'`.

Нажать «Выйти из шлюза». Клавиатура: **A / W / ↑** — вверх, **B / S / D / ↓** —
вниз. Мышью или пальцами — удерживать соответствующие подписанные кнопки [ЭМУЛ].
Отпускание останавливает действие и игровые часы. Кнопка руки зеркалит панель,
после переключения нужен нейтральный ввод и «Продолжить».

## Игровой маршрут

| Этап | Игровая задача | Открытие истории |
|---|---|---|
| Шлюз → поле | Добраться до поля обломков | Керне нужна батарея, а для чужого блока потребуется переходник |
| Поле: детали | Собрать три уцелевшие детали | В обломках есть гребёнка, обойма и проводник |
| Поле: сборка | Собрать переходник | Детали соединяются на полевом верстаке |
| Поле → остов | Добраться до остова с переходником | Путь к чужому блоку теперь имеет смысл |
| Остов: блок питания | Забрать аварийную батарею | Разведчик «Север-3» прибыл раньше нас; в журнале — знакомый сигнал |
| Остов → поле | Вернуться с батареей к полю обломков | Буря застала на знакомом маршруте |
| Поле → шлюз | Доставить батарею домой | Последний участок до Керны |
| Шлюз: завершение | Получить итог экспедиции | Батарея доставлена, журнал прежней экспедиции сохранён |

Точки заданы в `Model.LOCATIONS`: `airlock` (x=0.07), `debris` (x=0.40),
`scout` (x=0.91). Пока это заглушки в общем пространстве ущелья, а не три
отдельно загружаемые карты. На экране видны три названия и маркеры, в заголовке —
текущий переход; при входе меняются реплика Маяка и одна основная цель.

`Model.INTERACTIONS` содержит три точки: `debris_parts`, `field_workbench`,
`scout_power`. Они активны только на достигнутой остановке. После прибытия
нужно отпустить оба канала; затем A/B выполняют указанное взаимодействие.
После сбора деталей также требуется нейтраль перед сборкой. Переход к остову
открывается после готовности переходника. Возвращение — после получения батареи;
награда предлагается только после фактического достижения шлюза.

Ущелье проходится в обе стороны; при касании скалы продвижение блокируется,
игрок может изменить высоту. Буря даёт плавный видимый вертикальный снос,
пропорциональный intensity: слабый разрешённый сигнал остаётся управляемым.
Покой, BOTH и потеря потока замораживают ветер, частицы, задачи и часы.
Встречный сигнал восстанавливается через нейтраль; потеря потока, пауза и
возврат из фона — через нейтраль и явное «Продолжить».

В сборке каждый выполненный контакт сохраняется до окончания текущего запуска.
Зажатый канал не завершает несколько соединений: между ними требуется REST.
Оба испытания выполнимы обычными кнопками 0/1. В зажиме отдых сохраняет накопленное
удержание. В блоке питания нейтраль — отдельный требуемый шаг последовательности;
все его часы во время нейтрали стоят. Intensity=0 не набирает прогресс.

## Два испытания

### Зажим обломков: короткие усилия и широкая зона

Захват подводится к детали через OPEN/CLOSE; после входа в выделенную область
нужно набрать удержание короткими импульсами, отпуская каналы между ними.
Вертикальная полоса справа показывает длину текущего усилия, нижний индикатор —
удержание. В паузе положение, удержание и часы сохраняются.

| Параметр | Первая деталь, обучение | После её успешного зажима |
|---|---:|---:|
| Полная ширина зоны, доля поля | 0.34 | 0.26 |
| Нужное активное удержание, с | 0.45 | 0.65 |
| Длина одного усилия до отпускания, с | 0.85 | 0.65 |
| Ограничение игровой intensity | 0.55 | 0.65 |

Это игровые параметры нормализованных команд, не физические нормы усилия.
В обучении длинное усилие мягко останавливает захват и предлагает отпустить
каналы без ошибки. Затем выход из зоны во время удержания или слишком длинное
усилие дают повтор текущей детали. Положение захвата и готовые детали сохраняются.
Ошибка не повышает сложность; более строгий режим включается только после успеха.

### Блок питания: сигналы и окна открытия/закрытия

Три окна: **OPEN → REST → CLOSE → REST → OPEN → REST**. До каждого окна
виден крупный сигнал A или B и номер контакта; после правильного усилия он
сменяется явным «НЕЙТРАЛЬ / ОТПУСТИ ОБА». Завершённые контакты отмечены галочкой.
Здесь нет подведения курсора или удержания в пространственной зоне.

| Параметр | Первое окно, обучение | После его успешного завершения |
|---|---:|---:|
| Минимальная длительность действия, с | 0.16 | 0.25 |
| Запас на отпускание после сигнала, активные с | 1.80 | 0.90 |

Ожидание сигнала в REST бессрочное: окно начинается с разрешённой активной
команды после нейтрали, а не с настенных часов. Запас времени расходуется только
при продолжающемся активном усилии. Неправильный канал, слишком короткий контакт,
смена направления без нейтрали или игнорирование сигнала отпускания позволяют
повторить текущее окно; уже пройденные окна сохраняются. Ошибка первого окна
оставляет его обучающим. Повтор начинается после нейтрали, без отдельной кнопки.

При BOTH, WAITING_NEUTRAL, WAITING_RESUME, SUSPENDED, STALE, INVALID,
DISCONNECTED или pause_required оба испытания останавливают движение и таймеры.
После безопасного восстановления частичный контакт сохраняется; нейтраль от
resume/BOTH и последующие нейтральные heartbeat-кадры не считаются слишком
коротким усилием. Обычное раннее отпускание в активном окне — повтор этого окна.
Разрешённый REST может подтвердить нейтральный шаг, но не добавляет время.

Короткие нейтральные команды обрабатываются при доставке ядром, даже если
нейтраль и следующее направление пришли между двумя кадрами отрисовки.
При системной паузе сначала приостанавливается пайплайн и лишь затем очищаются
эмуляторы: техническая очистка не подтверждает взаимодействие и не создаёт ошибку.

Журнал доступен отдельной кнопкой; чтение приостанавливает ввод. После закрытия
следует явно продолжить. Повествовательные названия и формулировки — локальная
версия для согласования с сюжетной линией кампании.

## Архитектура и точки интеграции

- `expedition_model.gd` — независимое состояние, правила и сюжетные этапы;
  принимает `advance(delta, ControlCommand)`, не читает устройства и файлы.
- `clamp_trial.gd` и `power_trial.gd` — отдельные состояния двух испытаний,
  принимающие те же команды ядра; параметры и ошибки не меняют InputConfig.
- `quiet_signal.gd` / `.tscn` — отдельный запускаемый интерфейс и host.
- `signal_adapter.gd` — только эмуляция каналов клавиатурой/сенсором.
- `expedition_view.gd` — процедурное рисование; эффекты используют часы модели.

Локальный поток: адаптер → неизменённый ManualInputSource → неизменённый
InputPipeline → ControlCommand → модель. Профиль по умолчанию — существующий
эмулятор 0.55/0.40; heartbeat 50 мс, watchdog 250 мс. Сохранение игрока не читается.
Для самостоятельного режима читаются существующие `manual_pad.gd` и
`terminal_style.gd`; их исходники не менялись.

Пример подключения из host кампании:

```gdscript
var expedition = preload("res://game/side_expedition/quiet_signal.tscn").instantiate()
# При необходимости назначить существующий InputConfig ДО add_child().
expedition.input_config = approved_campaign_input_config
expedition.expedition_completed.connect(_on_quiet_signal_completed)
expedition.journal_added.connect(_on_quiet_signal_journal)
expedition.exit_requested.connect(_on_quiet_signal_exit)
add_child(expedition)
expedition.start_expedition(campaign_run_id)
```

Эмулятор сцены предназначен для самостоятельного прогона. Для подключения
общего аппаратного/кампанийного источника использовать модель и её
`advance(delta, ControlCommand)` из существующего координатора, сохранив
нейтраль/resume/watchdog. Новый аппаратный адаптер здесь не реализован.

Сигналы корня:

- `stage_changed(stage_id: String)` — переход этапа.
- `location_entered(location_id: String, entry_line: String)` — вход на точку;
  за полный проход: `airlock, debris, scout, debris, airlock`.
- `journal_added(entry: Dictionary)` — `{id, title, body}`, копия для сюжетного журнала.
- `expedition_completed(result: Dictionary)` — один результат успешного запуска.
- `exit_requested(result: Dictionary)` — запрос выхода с текущим результатом.
  Если подключён обработчик, переход выполняет владелец кампании. При отдельном
  запуске без обработчика «Выход» закрывает тестовую игру.

Формат локального результата (не изменение `contracts/`):

```json
{
  "schema_version": 1,
  "expedition_id": "quiet_signal",
  "run_id": "id назначает host или создаёт отдельный запуск",
  "completed": true,
  "battery_secured": true,
  "crafted_items": ["scout_adapter"],
  "reward_proposal": [{"item_id": "emergency_battery", "amount": 1}],
  "discoveries": ["prior_expedition"],
  "visited_locations": ["airlock", "debris", "scout", "debris", "airlock"],
  "journal": [],
  "stats": {
    "active_seconds": 0.0, "wall_contacts": 0,
    "clamp_failures": 0, "power_failures": 0,
    "clamp_active_seconds": 0.0, "power_active_seconds": 0.0
  }
}
```

Это предложение награды. Сцена не начисляет предметы, не регистрирует миссию
на карте, не записывает склад и не создаёт шкалы запасов. До возвращения
`reward_proposal` пуст. Владелец кампании определяет однократность награды по
`expedition_id` и защищает обработку одного запуска по `run_id`; не начислять
повторно и по completed-сигналу, и по последующему выходу. Повтор отдельного
прототипа начинает новый локальный запуск с пустыми деталями и новой батареей.

## Ограничения и передача

Android APK, физический телефон, реальные датчики и эргономика руки не проверены.
Визуал — кодовые примитивы, без внешних ассетов и звуковой дорожки.
Активное время идеального контроллера — около 30 с при полном сигнале и 115 с при 0.65;
чтение, реакция и ошибки игрока в эти значения не входят.

Для интеграции переносится только `game/side_expedition/`; затем подключаются
карта, сюжет и склад владельцем кампании. Shared-сцены, InputPipeline, contracts,
project.godot, экспорт, основная кампания и глобальные evidence-файлы не правились.
В соответствии с этой изоляцией журнал ИИ находится здесь:
`game/side_expedition/evidence/ai-log.csv`; запись о визуале — в соседнем assets.csv.
