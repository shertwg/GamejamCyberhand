# Внутренний контракт v1 — предложение для утверждения Августом

Это НЕ API Моторики и НЕ медицинские данные. Не менять формат молча. После получения полного ТЗ сверить все поля.

03.11.2026 Август утвердил описанные ниже настройки эмулятора и правила REST/BOTH/восстановления. Это внутренние решения команды; полный текст ТЗ организаторов отсутствует. Остальные предложения контракта не объявляются автоматически утверждёнными.

`InputSource → InputFrame → Decoder → ControlCommand → Gameplay → GameEvent → SessionSummary → UI / LocalStore`.

- InputSource подменяемый: ручная панель, клавиши для разработки, воспроизведение трассы; позже возможен настоящий адаптер.
- InputFrame: schema_version=1, seq — возрастающий номер, timestamp_ms — монотонное время от начала потока, channel_a/channel_b — нормализованные 0..1, connected, source.
- Для connected=false оба канала 0, команды сбрасываются; игра приостанавливается. Устаревший/невалидный кадр не вызывает захват. Начальный таймаут потока — 250 ms, технический параметр команды, подлежит проверке.
- Decoder хранит отдельные пороги включения/выключения каждого канала (порог выключения ниже включения). Утверждённый стартовый профиль `InputConfig.emulator_profile()`: A и B on=0.55, off=0.40; heartbeat=50 ms, timeout=250 ms. Каналы настраиваются независимо. Это игровые настройки эмулятора, не медицинские нормы. Heartbeat обеспечивает вызывающий код; watchdog `tick()` вызывается регулярно даже при отсутствии кадров и при блокировке ввода.
- ControlCommand: direction — REST, OPEN, CLOSE или BOTH; intensity — нормализованное значение 0..1. Для REST/BOTH intensity=0. Decoder использует независимые пороги включения/выключения с гистерезисом; после активации intensity=clamp((value-on)/(1-on), 0, 1). В полосе гистерезиса направление сохраняется при нулевой интенсивности. Игра использует intensity для пропорциональной скорости открытия/закрытия. A→OPEN, B→CLOSE; переназначение через профиль остаётся будущей работой.
- REST: безопасная нулевая команда, `state=REST`, `pause_required=true`; будущая игра останавливает движение и игровые часы. REST не ошибка. Следующая разрешённая валидная OPEN/CLOSE снимает именно паузу ввода, но не пользовательскую паузу.
- BOTH: intensity=0, `state=BOTH`, `pause_required=true`, reason=opposing_channels для мягкого объяснения в будущем UI. Включается отдельная BOTH-блокировка: оставшийся активным канал не возобновляет движение (`WAITING_NEUTRAL`, reason=both_requires_neutral). Свежий валидный кадр с обоими каналами <= их off снимает эту блокировку и выдаёт REST; последующая OPEN/CLOSE разрешена без экранного resume.
- DISCONNECTED/INVALID/STALE: REST/0 и `pause_required=true`, сброс гистерезиса. Восстановление только через свежий нейтральный кадр (`WAITING_RESUME`) и явный `request_resume()`. Зажатые каналы дают `WAITING_NEUTRAL`. BOTH во время восстановления не отменяет требование resume. SUSPENDED и запуск нового потока используют тот же строгий барьер. Диагностическая reason исходного отказа сохраняется в состояниях ожидания; новый отказ может заменить её.
- Метаданные ядра различают REST, BOTH, ACTIVE, WAITING_NEUTRAL, WAITING_RESUME, DISCONNECTED, INVALID, STALE, SUSPENDED и NOT_STARTED. При `pause_required=true` будущая интеграция останавливает движение и игровое время; источник/часы watchdog продолжают работать. Ядро ещё не подключено к игре и само её таймерами не управляет.
- UI отправляет start_session(level_id), pause, resume, retry, exit. UI не двигает захват напрямую.
- Gameplay принимает состояние и выдаёт события action_started, action_succeeded, action_failed, level_completed. У события есть session_id, attempt_id, level_id, timestamp_ms, reason; повторная доставка того же event_id не должна удваивать счёт.
- SessionSummary: schema_version, level_id, active_ms, attempts, successes, unwanted_both_ms, scored_window_ms, median_reaction_ms или null, hold_in_target_ms, hold_target_ms, source. Нулевой знаменатель → null, не 0% и не NaN.

## Метрики

- Ядро ввода не создаёт событий ошибки и не увеличивает счётчики: метрики пока не реализованы. REST, BOTH и отказ потока сами по себе не штрафуют игрока; обычный покой, обучение, намеренный BOTH и отсутствие сигнала не добавляют ошибку. Диагностическая reason не является action_failed. Длительность нежелательного BOTH может учитываться отдельно в явно заданном оценочном окне, но не превращается автоматически в штраф/неудачную попытку.

- Успешность = successes/attempts, если attempts>0.
- Нежелательная совместная активация = unwanted_both_ms/scored_window_ms. Окна задаются заданиями, пауза и обучение отдельно; намеренный BOTH не считать ошибкой.
- Реакция: время от показанной команды до первого корректного состояния в соответствующей попытке. Медиана только по валидным ответам; промахи показывать отдельно.
- Точность удержания = hold_in_target_ms/hold_target_ms в заданиях на удержание. Сравнивать результаты только при одинаковых настройках/сложности; на эмуляторе это показатели тестового ввода, не физиологического прогресса.
- Задержку приложения измерять отдельно: от получения кадра до отображения эффекта. Цель команды — p95 ≤150 ms на выбранном устройстве; это не факт, пока не измерено, и не включает задержку настоящего датчика.

## Заглушки для независимой работы

Антон использует пример SessionSummary из examples. Дима использует воспроизведение ControlState через временный локальный адаптер. Август реализует реальные классы/сигналы и подключает их в корневой сцене. Это позволяет UI и gameplay работать независимо до интеграции.
