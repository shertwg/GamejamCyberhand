# Фундамент «Рейнджер на враждебной планете» — с чего начать (08.11.2026)

Это рабочее состояние после переноса прототипа на концепцию из `planning/product.md`. Полное ТЗ организаторов по-прежнему не сверено.

## Что уже работает (проверено headless на Godot 4.4.1, см. `evidence/ai-log.csv`, RANGER-FOUNDATION)

Старт → выбор миссии / руки → миссия → «Продолжить» → проход маршрута → итог (апгрейд базы, запись экспедиции, метрики, адаптация) → повтор / следующая миссия. Прогресс сохраняется локально.

| Миссия | id | Что тренирует |
|---|---|---|
| Обучение: калибровка манипулятора | `tutorial` | A/B, покой, BOTH без штрафа |
| 1. Клапан охлаждения | `repair-1` | базовое переключение каналов, широкие проходы |
| 2. Энергоячейка генератора | `repair-2` | удержание курса в зоне стабилизации |
| 3. Герметизация и маяк | `repair-3` | точная доводка, узкие проходы |

Адаптация: между попытками, шаг −1/0/+1 (±10% темпа, ±0.04 просвета). 2 чистых прохода подряд → +1; 2 прохода с BOTH ≥ 1 с → −1. Отключается в профиле. Пороги ввода адаптация не меняет.

## Карта файлов и владельцы

| Файл | Владелец | Что это |
|---|---|---|
| `game/core/input_*.gd`, `manual_input_source.gd`, `control_command.gd` | Август | безопасный пайплайн ввода (не трогать без капитана) |
| `game/core/game_event.gd` | Август | событие gameplay → core, дедуп по `event_id` |
| `game/core/session_tracker.gd` / `session_summary.gd` | Август | метрики попытки, null при нулевом знаменателе |
| `game/core/local_store.gd` | Август | `user://ranger_profile_v1.json`, защита от битого файла |
| `game/core/replay_input_source.gd` | Август | 6 воспроизводимых трасс (`clean_a`, `clean_b`, `rest`, `opposing_both`, `threshold_jitter`, `disconnect_recovery`) |
| `game/core/level_config.gd` | Август ↔ Дима | данные миссий и правило адаптации. Дима предлагает параметры, Август вносит |
| `game/gameplay/course.gd` | Дима | маршрут, коллизии, зона удержания, выдача `GameEvent` |
| `game/gameplay/prototype.gd` | Август (временно) | композиция экранов + интеграция; Антон забирает экраны в `game/ui/` |
| `game/ui/manual_pad.gd` | Антон | подписанный эмулятор A/B, зеркалирование, шкала с порогами |
| `game/content/copy-ru.md` | Арина | все тексты (источник правды) |
| `game/content/copy_catalog.gd` | Август | тексты из copy-ru.md в коде; Арина меняет только .md, Август переносит |
| `qa/prototype_smoke.gd` | Алиса (кейсы) / Август (код) | автотест; должен оставаться 0 failures |

## Проверка перед любой передачей Августу

```powershell
$g='D:\Godot\Godot_v4.4.1-stable_win64_console.exe'
& $g --headless --path . --editor --import
& $g --headless --path . --script res://qa/prototype_smoke.gd --max-fps 120   # ждём: failures=0
```

Строка `ERROR: Parse JSON failed` в выводе ожидаема — это тест битого сохранения. Тест пишет только `user://smoke_*.json`, профиль игрока не трогает.

## Известные ограничения

- Только desktop headless; APK с этим кодом не собирался и на телефоне не проверялся.
- Tutorial — облегчённый маршрут с подсказкой, а не пошаговый сценарий с проверкой действий.
- Визуал процедурный (прямоугольники/круги), внешних ассетов нет.
- Правило адаптации и пороги — гипотезы команды, не медицинские нормы.
