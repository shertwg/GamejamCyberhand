# Репозиторий и правила интеграции

Цель: https://github.com/shertwg/GamejamCyberhand. Публичный репозиторий успешно клонирован; на момент клонирования он пустой. Основная локальная ветка — main, origin указывает на указанный адрес. GitHub CLI в сессии агента по-прежнему возвращает 401, поэтому права записи агента не подтверждены. Настройки защиты GitHub не изменены. Первый коммит и отправку выполняет капитан.

## Ветки

- `main` — последняя принятая версия, на ней всегда собирается приложение.
- `feat/avgust-core` — сигналы, хранилище, интеграция, сборка.
- `feat/anton-ui` — отдельные сцены экранов.
- `feat/dima-gameplay` — игровая сцена и логика уровней.
- `content/arina` — тексты и параметры контента.
- `qa/alisa` — тест-кейсы и результаты.

Ветки стартуют от main; после первой интеграции дальнейшие задачи желательно делать короткими ветками `feat/ID-description`. Дополнительную develop не вводим: для 12 дней она добавит лишний этап. Интегрируем ежедневно, до конца дня не оставляем три независимые версии игры.

## Владение файлами

| Владелец | Зона | Не изменяет без согласования |
|---|---|---|
| Август | game/core, contracts, tools, корневая сцена, project.godot, export_presets.cfg, .github | Все общие настройки меняет с уведомлением команды |
| Антон | game/ui | Ядро, gameplay, корневую сцену и autoload |
| Дима | game/gameplay | UI, ядро и общие настройки |
| Арина | game/content, материалы для питча | Код и сцены |

Антон вызывает события навигации, Дима выдаёт игровые события, Август соединяет сцены в композиционном корне. Не редактировать одновременно один .tscn. Общие ассеты импортируются капитаном; параметры уровня лежат отдельно от сцены.

## Коммиты по текущему решению капитана

Все коммиты, push и merge выполняет Август. Участники готовят изменения в своих локальных копиях и присылают список файлов/патч, шаги проверки и ограничения. Для бинарных ассетов — файлы и источник, поскольку текстовый diff их не переносит. Капитан проверяет изменения, коммитит в соответствующую ветку и интегрирует в main. Не отправлять всю папку с .godot и локальными настройками.

Это создаёт нагрузку на Августа: планируем два окна приёмки в день. Если он позже разрешит участникам собственные коммиты в feature-ветках, сохранить за ним review и squash merge в main. До такого решения агенты не коммитят.

## Настройка GitHub капитаном

1. Уточнить default branch. Если сейчас она не main, сначала согласованно изменить это либо адаптировать setup-local-branches.ps1.
2. Оставить права записи капитану; остальные работают с локальными копиями/патчами. Не менять доступность приватного репозитория ради настройки.
3. После первого коммита создать локальные ветки скриптом. Публикует ветки капитан, когда доступ к GitHub работает.
4. Скопировать .github/CODEOWNERS.example в .github/CODEOWNERS, вписать настоящий GitHub-логин Августа. CODEOWNERS сам по себе не запрещает merge.
5. Если тариф/тип репозитория поддерживает rulesets, защитить main: запрет force push и удаления, изменения через PR. Настроить права и исключение для капитана так, чтобы он мог интегрировать сам: не требовать его одобрения собственных PR. Возможности тарифа проверить в интерфейсе; не считать защиту включённой без проверки.
6. Когда появится проект, добавить CI на закреплённой версии 4.4.1: импорт проекта и meaningful проверки декодера/метрик. CI сейчас не заявлен готовым; в пакете нет приложения.
7. APK хранить как файлы релиза/материалы сдачи, ключи подписи держать вне репозитория. Доступ экспертов к исходникам проверить до дедлайна.
8. Не назначать open-source лицензию автоматически: сначала учесть условия конкурса, собственные права и лицензии зависимостей.

## Приёмка любой задачи

Условия тикета выполнены; изменения в своей зоне; нет неоговорённой смены контракта; фактические проверки записаны; нет новых критических ошибок; изменения ИИ и источники материалов указаны. Для игрового поведения — проверка APK капитаном/Алисой. Каждая приёмка должна оставлять воспроизводимую версию.
