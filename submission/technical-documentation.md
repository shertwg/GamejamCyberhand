# Техническая документация · Маяк / Последний свет

**Команда shertwg · 0.9.0-rc1 · 11 ноября 2026**

## 1. Запуск и сборка

Готовая Android-сборка — `kerna-android.apk`. Установите её и запустите «Маяк: Последний свет». Нужны ARM64 или x86_64 и OpenGL ES 3.0. Манифест указывает API 21 как минимум и API 34 как целевой уровень. Проверенная среда указана в `verification.md`. Используется отладочная подпись Godot. При конфликте подписей для проверки подойдёт отдельный профиль или устройство. Удаление старой установки удаляет её локальный прогресс.

Для запуска исходников откройте `project.godot` в Godot 4.4.1, дождитесь импорта и нажмите F5. На первом запуске показывается вступление. Для отдельной проверки вылазки откройте `game/side_expedition/quiet_signal.tscn` и нажмите F6. Для экспорта установите шаблоны Godot 4.4.1, JDK 17 и Android SDK с Build Tools 34, укажите пути в настройках редактора и используйте `Android Debug APK` в меню экспорта. Пример команды:

```text
godot --headless --path . --editor --export-debug "Android Debug APK" builds/android/kerna-submission.apk
```

Игра работает локально. Манифест содержит разрешение VIBRATE для тактильного отклика. Сохранения находятся в каталоге `user://` Godot. Ключи подписи и пути к SDK хранятся в настройках среды сборки.

## 3. Контракт и восстановление ввода

`ManualInputSource → InputFrame → InputValidator → InputDecoder → InputStreamGuard → ControlCommand → SessionCoordinator → ремонт`

Кадр v1 содержит `seq`, монотонный `timestamp_ms`, каналы `channel_a` и `channel_b` в диапазоне 0..1, `connected` и `source`. Схема и примеры находятся в `contracts/`. Декодер выдаёт REST, OPEN, CLOSE и BOTH. Начальные пороги эмулятора ON 0.55 и OFF 0.40 задаются для каждого канала отдельно. Период кадров 50 мс, таймаут 250 мс. Игровой процесс принимает команды через ядро. Watchdog вызывается даже при отсутствии новых кадров.

REST останавливает движение и позволяет фиксировать некоторые этапы ремонта. BOTH требует нейтрали. После устаревшего кадра, разрыва, ошибки или системной паузы ядро ждёт свежую нейтраль и явное продолжение. Свежая игровая сессия с нейтральным экранным эмулятором разрешает начать ремонт сразу. Внешний источник реального сигнала должен реализовать тот же контракт, включая собственную калибровку, достоверность кадров и обработку отключения.

## 4. Прогресс, метрики и хранение

`StationState` сохраняет состояние корабля, припасы, урожай, инвентарь и журнал. `LocalStore` хранит профиль ввода, выбранную руку и результаты; повреждённый профиль восстанавливается с настройками по умолчанию. `PlayerSettings` хранит звук и доступность. Вылазка имеет собственное состояние и защиту от двойной выдачи награды. Текущий ремонт можно повторить с начала после перезапуска.

`SessionSummary` хранит активное время, число попыток и успехов, время нежелательного BOTH в оценочном окне, удержание в целевой зоне и медиану реакции при наличии наблюдений. При нулевом знаменателе соответствующая доля отсутствует. Эти данные описывают игровой ввод. На их основе ещё не делались медицинские выводы. Для сопоставления попыток следует сравнивать одинаковые режимы и настройки.

## 5. Повторение проверок

Выполните команды из корня проекта:

```text
godot --headless --path . --editor --import
godot --headless --path . --script res://qa/campaign_smoke.gd
godot --headless --path . --script res://qa/prototype_smoke.gd
godot --headless --path . --script res://qa/station_smoke.gd
godot --headless --path . --script res://game/side_expedition/tests/smoke.gd
python tools/validate_missions.py --input game/content/missions.json
```

Отчёт по версии и ограничениям находится в `verification.md`, файлы запуска — в `checks/` комплекта сдачи. Для дальнейшей проверки на телефоне выполните чистый запуск без сети, первый ремонт, сворачивание на удержании, явное восстановление после нейтрали и перезапуск с сохранённым прогрессом. Физический протез потребует отдельной проверки, включая задержку от кадра до видимого эффекта и комфорт управления.

## 6. Границы соответствия Потоку 1

Рычаг формирует пропорциональный сигнал, ядро применяет пороги с гистерезисом. Отдельного пользовательского переключателя между пороговым и пропорциональным режимами в этой сборке нет. Рычаг выбирает один канал, состояние BOTH проверяется отдельными трассами ядра. Навигация и хозяйственные действия выполняются касаниями, ремонт принимает команды общего адаптера. Сложность меняется между попытками по результатам, детали в `game/core/level_config.gd` и `game/gameplay/session_coordinator.gd`.

Требование задержки не более 100 мс из командного брифа для Потока 1 пока не подтверждено измерениями на телефоне. Доля времени в заданиях с критическими таймингами на живом игроке не измерялась. Android-сборка проверена в объёме `verification.md`.
